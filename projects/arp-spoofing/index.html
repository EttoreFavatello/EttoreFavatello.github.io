ARP Spoofing

Attacco Man-in-the-Middle tramite ARP cache poisoning, con intercettazione del traffico e sviluppo di strumenti Python per automatizzare attacco, ripristino e rilevamento. Progetto offensivo e difensivo a scopo didattico.

[ ← home ] [ codice su github ]

// Nota etica

L'intero progetto è stato sviluppato e testato in un laboratorio isolato — macchine virtuali su rete privata — esclusivamente a scopo didattico. L'ARP spoofing eseguito su reti non autorizzate è illegale. Lo scopo di questo lavoro è comprendere il funzionamento dell'attacco per saperlo riconoscere e difendere.

// Overview

Il protocollo ARP non prevede alcun meccanismo di autenticazione: una macchina si fida ciecamente delle risposte ARP che riceve. Questo progetto sfrutta tale debolezza per inserirsi tra due host (una vittima e il gateway), intercettando il traffico che si scambiano, per poi sviluppare gli strumenti di automazione e di difesa.

// Setup del laboratorio

L'ambiente è composto da macchine virtuali isolate su rete privata:

  • Kali Linux — attaccante, posizionato come Man-in-the-Middle
  • Metasploitable — macchina vittima
  • pfSense — firewall/router, gateway della rete

Tutto il traffico tra la vittima e il gateway viene fatto transitare attraverso la Kali, permettendo l'analisi del traffico intercettato.

// Fasi del progetto

01
Attacco manuale
Avvelenamento delle cache ARP con il tool arpspoof (suite dsniff) e analisi in tempo reale del traffico intercettato tra le due vittime tramite Wireshark.
02
Automazione attacco
Script Python (Scapy) che avvelena entrambi gli estremi in loop, abilita l'IP forwarding per non interrompere la connettività, e al Ctrl+C ripristina le cache ARP originali cancellando le tracce.
03
Automazione difesa
Script Python passivo che cattura il traffico ARP, costruisce una tabella delle associazioni IP-MAC e genera un'allerta quando un MAC inizia a dichiarare un IP diverso da quello già registrato.

// Strumento 1 — Attacco e ripristino

Il primo programma avvelena entrambi gli estremi della comunicazione: comunica alla vittima che il gateway si trova al MAC dell'attaccante e, simmetricamente, comunica al gateway che la vittima si trova al MAC dell'attaccante. L'invio è ripetuto in un ciclo continuo per mantenere le cache "avvelenate".

Per non interrompere la connettività della vittima — cosa che trasformerebbe l'attacco in un semplice Denial of Service — si abilita l'IP forwarding sulla macchina attaccante, che inoltra il traffico verso il gateway reale: la vittima continua a navigare mentre il traffico resta intercettabile.

Alla chiusura del programma (Ctrl+C), una routine di ripristino invia risposte ARP con i MAC originali, riportando le tabelle allo stato corretto e cancellando le tracce dell'attacco.

// Strumento 2 — Rilevamento

Il secondo programma agisce in modo passivo: cattura tutto il traffico ARP della rete e costruisce progressivamente una tabella delle associazioni osservate. Quando rileva un'incoerenza tipica dell'avvelenamento — ovvero un MAC che inizia a dichiarare un indirizzo IP diverso da quello già registrato — genera un messaggio di allerta.

È il rovescio difensivo dell'attacco: dimostra come lo stesso comportamento anomalo che rende possibile lo spoofing possa essere usato per individuarlo.

// Esecuzione

Avvio dell'attacco (richiede IP forwarding e privilegi di root):

  • sudo sysctl -w net.ipv4.ip_forward=1
  • sudo python3 arp_attack.py <ip_vittima> <ip_gateway>

Avvio del rilevatore, in ascolto passivo sul traffico ARP:

  • sudo python3 arp_detector.py

// Competenze applicate

Protocollo ARP, attacchi Man-in-the-Middle, IP forwarding, analisi del traffico con Wireshark, scripting offensivo e difensivo in Python con Scapy, virtualizzazione e progettazione di reti isolate.
